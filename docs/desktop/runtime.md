# Packaged backend and local integrations

My Own Dots bundles its Node backend, production JavaScript dependencies, Integrator Python source and lockfile, folder helper, speech worker, and PostgreSQL Compose configuration. Electron's bundled Node starts the API server; no system Node is required for normal launch. The app does not contain credentials, databases, virtual environments, downloaded speech models or authenticated AI CLIs.

New installations keep `.env`, SQLite and optional integration runtimes in the application's userData `workspace` folder (normally `~/Library/Application Support/My Own Dots Desktop/workspace`). Existing workspaces can be selected in the native recovery window, or by setting `DOTS_WORKSPACE_DIR` before launch. Selection persists in userData `workspace-location.json`. Existing databases are used in place: relative `DATABASE_PATH` values resolve against the workspace folder; absolute paths remain absolute. `DOTS_WORKSPACE_DIR` overrides persisted selection. Development uses the source workspace unless explicitly overridden.

An occupied backend address is reused only when its authenticated `/api/desktop/identity` matches this workspace's canonical SQLite path. A different or older service produces an actionable conflict; the app never silently switches ports and starts a second runner. To deliberately attach to an existing local Dots server, set `DOTS_WORKSPACE_URL=http://127.0.0.1:4310`. Supply its `OWNER_TOKEN` in your workspace `.env` if needed. Explicit attachment also supports the existing `/api/state` service shape. External servers are never stopped by Quit. Updated server entrypoints use an atomic `.runtime-lock` beside SQLite to prevent duplicate runners even across different ports. A lock whose PID no longer exists is reclaimed under an atomic ownership guard; malformed locks require inspection. An existing `.runtime-lock.guard` is never reclaimed automatically, because another process may be actively replacing a stale lock. If its ownership check remains blocked, confirm every backend is stopped before inspecting and removing the empty guard directory. Close the running backend before changing its database configuration. Older backends started before this migration do not hold a runtime lock: close them before changing PORT against the same data. The unchanged default port safely reports a conflict, and explicit attachment preserves the running older service.

Local conversations need PostgreSQL. If the configured local port is unavailable and matches the bundled configuration, the app runs Docker Compose using the existing `my-own-dots-local` project and its conversation volume for legacy workspaces. Newly generated configurations save a stable scoped `COMPOSE_PROJECT_NAME`; an explicitly configured project name is preserved. When Docker or PostgreSQL cannot start, the app still opens SQLite Spaces/pages and reports an actionable warning; local chat needs the database before it can connect. Install and open Docker Desktop, then Retry. For an already managed database, configure `LOCAL_DATABASE_URL` instead. Compose startup is bounded and never resets volumes. Docker may need to obtain the pinned PostgreSQL image on first use; no AI or speech models are downloaded automatically.

Subscription inference needs your provider CLI installed and signed in, plus the Integrator's Python dependencies. Install `uv`, then run the following explicitly, substituting the actual app and workspace locations:

```sh
ELECTRON_RUN_AS_NODE=1 "/Applications/My Own Dots.app/Contents/MacOS/My Own Dots" "/Applications/My Own Dots.app/Contents/Resources/app/app/support/setup-desktop-integrations.mjs" "$HOME/Library/Application Support/My Own Dots Desktop/workspace"
```

If no interpreter is configured, the owned backend sets `UV_PROJECT_ENVIRONMENT` to `workspace/integrations/llm/.venv`, so the Integrator fallback cannot create a virtual environment inside the signed app. An explicit `UV_PROJECT_ENVIRONMENT` is preserved. This was verified offline with the installed uv runtime.

This copies the shipped Python source into `workspace/integrations/llm/python`, installs its locked dependencies there, and saves `MYOWN_LLM_PYTHON` if unset. No files inside the signed application are modified. Retry the app after setup. Existing `MYOWN_LLM_PYTHON`, `CODEX_BIN` and `AGENT_BIN` settings are preserved. Finder-launched apps inherit a smaller PATH than terminal sessions; configure absolute CLI paths if your provider executable is not found.

Local speech remains optional and disabled by default. Follow the shipped `scripts/local-voice/README.md` and pinned manifest, and point `LOCAL_VOICE_PYTHON` and `LOCAL_VOICE_ASSETS` at persistent locations outside the application. Speech workers and folder helper code load from the application runtime independently of the selected workspace folder. Approved folder access still requires Python 3.11+ (`DOTS_FOLDER_PYTHON` can override it). Computer/browser services, managed conversation credentials and connected apps remain separately configured integrations. Missing AI configuration can be completed through the existing Settings screens; the API and desktop shell remain available.

The server entrypoint serves APIs and authenticated identity only, including `npm start`. Electron supplies all production frontend assets. Vite remains a deliberate source development harness for renderer iteration (`npm run dev`).
