# Daily conversations and call history

Dot's native Chat and Talk entries now resolve one conversation per owner, Dot, and local calendar day. The default title is `YYYY-MM-DD`; renaming does not change its daily identity. An active call stays in its original conversation across midnight. Explicit history links and manually created conversations remain separate.

The former clutter had two causes: delegated task workers appeared in conversation navigation, and native entry reused any selected conversation. Durable task records now mark workers for navigation filtering without removing their execution records, approvals, memory sources, or direct links. Daily creation is idempotent. Unified SQLite creates the canonical thread and binding in one transaction. External conversation providers use the same reserved identity on retry; creation across two stores cannot be atomic.

Each new call owns an expandable transcript item. Host-written message IDs associate canonical captions, replies, and every task-receipt generation with the original call, independently of audio playback. Later results stay there even while another call is active. The call's start anchor stabilizes its position when an earlier typed response delays caption persistence. Task status and approval links remain available, including more than twenty tasks. Saved-message links expand the containing item and focus the original article.

Schema 9 adds call membership metadata. Existing calls retain their legacy layout; no messages are guessed into groups from timestamps, prefixes, or cached raw transcripts. Existing history remains owner-readable; suppression and model context rules are unchanged. Old pending receipts can still be delivered after migration. Archive validation checks membership whenever the table is present, including legacy metadata and older supported schemas.

Verification covers actual storage workers and restart recovery; daily API scope, rename and midnight behavior; native host/preload and React intent cancellation; late native task results; ordinary voice persistence after hangup; and partial remote SDK output. Focused browser checks use production transcript/list components with disposable fixture data, testing approval links, collapsed/expanded groups, saved-message focus, dark/compact layouts, and absence of overlapping text or horizontal overflow.
